일일브리핑 웹 자동 수집 적용

GitHub에서 app.py와 같은 폴더의 아래 두 파일을 교체하세요.
1. data_services.py
2. briefing.html

Commit changes 후 Streamlit 관리 메뉴에서 Reboot app을 실행합니다. 홈에서 일일브리핑 작성기로 이동하여 보고일을 선택하고 작성기 열기를 누릅니다. 이미 열린 작성기는 홈으로 나갔다 다시 들어가야 새 자료를 수집합니다.

기존 app.py와 한전 관련 파일은 유지하세요. requirements.txt는 앞서 lxml을 추가한 파일을 계속 사용하면 됩니다.

연결 내용
- 도정 키워드: 원본 ScrapMasterBridge.ps1과 같은 날짜별 POST 요청 및 period_member_word_score_pair 데이터
- 신문 1면 단어쌍: 원본과 같은 GET 요청 및 today_1_word_score_pair 데이터
- 신문 1면 단어쌍은 오늘만 지원하며 과거 날짜로 재표시하지 않음
- 웹에서는 서버 수집 자료를 작성기에 전달하여 워드클라우드를 자동 생성. PC의 RUN.cmd 또는 로컬 연결 프로그램을 요구하지 않음
- HTML 내부 버튼은 수집 자료 다시 적용. 다른 날짜 조회나 새 자료 수집은 홈 -> 일일브리핑 -> 보고일 선택 -> 작성기 열기
- 직접 HTML을 실행하는 기존 PC 방식의 호출은 유지
- 정상 작동이 확인된 연합뉴스 헤드라인 함수는 변경하지 않음

검증
헤드라인 테스트 7개, 키워드 테스트 8개, 웹 자료 적용 및 워드클라우드 자동 생성 흐름 테스트를 통과했습니다. 원본 로그에는 두 종류 모두 100개 수집 성공 기록이 있습니다. 현재 분석 환경의 직접 접속은 HTTP 403으로 제한되어 Streamlit 배포 서버의 실제 접속 성공 여부는 배포 후 확인해야 합니다.
